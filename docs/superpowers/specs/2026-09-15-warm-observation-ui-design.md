# BYGuardian UI·UX 개선 — 따뜻한 관찰 노트

작성일: 2026-09-15

상태: 디자인 방향 사용자 승인 완료. 이 문서는 구현 전 검토할 상세 명세다.

## 1. 목표와 근거

40~70대 보호자가 짧은 시간에 관찰을 남기고 다음 진료에서 질문을 꺼낼 수 있게 한다.
첫 화면에서 서비스의 용도와 다음 행동을 이해하고, 기록·질문·설정 사이를 쉽게 이동하도록 개선한다.
오프화이트와 잉크 블루를 사용하는 차분하고 따뜻한 노트의 시각적 인상을 채택한다.

확인한 현재 상태:

- 배포 랜딩은 제목·설명·버튼을 좁은 한 열에 배치해 서비스의 산출물이 드러나지 않는다.
- 입력 화면은 같은 흰색 선택 상자가 반복되고, 진행 막대만으로 현재 위치를 이해해야 한다.
- 기존 설계의 작은 보조 목록·강조 금지·빈 화면 유지 지침이 합쳐져 정보 위계가 약해졌다.
- 원래 색상 규칙은 색 전체 금지가 아니라 환자의 좋고 나쁨을 색으로 판단하지 않는다는 뜻이다.
- 최신 원격 main은 `e6f7692`다. 모바일 표 스크롤 안내, 과거 진료일 검증, 코드 확인,
  접근성·404·온보딩 안내 등의 최근 수정이 포함되어 있다.
- 현재 로컬 main에는 QA 보고서 커밋 `e7a35a7`이 별도로 있다. 구현 시작 시 두 이력을
  보존해 최신 수정 기반에서 진행한다. 원격 구현과 로컬 QA 산출물의 차이를 삭제 요청으로 해석하지 않는다.

## 2. 제품 경계와 디자인 규칙 개정

색은 브랜드, 화면의 구획, 사용자 조작과 선택을 표현한다. 환자의 호전·악화·위험도를 표현하지 않는다.

- 모든 도움 수준과 관찰 변화에는 같은 중립적 표현 체계를 쓴다.
- 선택은 같은 블루와 체크·테두리·접근성 상태를 함께 사용한다. 특정 답만 긍정 색으로 칠하지 않는다.
- 날짜·주차·질문 순번·입력 진행 단계는 정보 표기다. 건강 점수·회복률·등급은 도입하지 않는다.
- 상태 판정 문구, 카탈로그 라벨, 질문과 관찰 근거는 기존 서버 결과를 그대로 표시한다.
- 입력 실패는 문구·아이콘·포커스로 알린다. 색만 바꿔 오류를 전달하지 않는다.
- '누를 수 없는 카드는 장식'이라는 기존 구현 주석은 수정한다. 읽기 전용 면도 정보 묶음에
  사용할 수 있으며, 화살표·눌림 효과·포인터는 실제 조작 요소에만 붙인다.
- '빈 화면을 채우지 않는다'는 가짜 관찰이나 건강 해석을 추가하지 않는다는 의미로 적용한다.
  기록 완료·현재 주차·사용 가능한 다음 행동을 정돈해 보여주는 것은 허용한다.
- 작은 글씨와 낮은 대비로 보조 기능을 숨기지 않는다. 크기·배치·버튼 형태로 우선순위를 만든다.

이 명세는 기존 프론트 설계의 시각 표현과 위의 지침을 개정한다. 제품의 비판정 원칙과 API 계약은 유지한다.
구현 시 기존 설계 문서에 이 개정 문서 링크를 추가하고 모순되는 주석을 함께 갱신한다.

## 3. 시각 언어

| 역할 | 값 | 용도 |
| --- | --- | --- |
| 페이지 배경 | `#F7F5F0` | 따뜻한 오프화이트 |
| 기본 면 | `#FFFFFF` | 기록 노트, 입력, 질문 |
| 보조 면 | `#EEE9DF` | 날짜·완료 안내·보조 정보 |
| 본문 | `#243247` | 제목과 핵심 내용 |
| 보조 글자 | `#586476` | 설명과 날짜, 출처 |
| 브랜드·주 행동 | `#365D83` | 주 버튼, 링크, 포커스 |
| 선택 배경 | `#E8EFF5` | 선택된 항목 |
| 장식 경계 | `#DDD7CB` | 읽기 전용 면의 구분선 |
| 입력 경계 | `#7C8794` | 입력과 선택 컨트롤의 식별 가능한 경계 |

색상 이름은 용도로 정의하며 `good`, `bad`, `recovery` 같은 환자 평가 이름을 만들지 않는다.
일반 글자는 배경 대비 4.5:1 이상, 컨트롤 경계와 포커스는 인접 면 대비 3:1 이상으로 검증한다.

- 글꼴: 현재 한국어 시스템 글꼴을 유지한다. 본문 18px, 보조 16px, 제목 26~32px.
- 줄 높이: 본문 1.6, 제목 1.3. 긴 한국어와 큰 글자 설정에서 줄바꿈을 허용한다.
- 간격: 4·8·12·16·24·32·48px 체계. 모바일 좌우 20px, 작은 화면은 16px.
- 노트 면: 반경 20px, 내부 24px, 얕은 그림자. 선택·입력은 반경 12px.
- 주 버튼: 높이 최소 56px. 기타 조작도 터치 영역 최소 48px.
- 아이콘: 일정·노트·질문·공유를 나타내는 같은 선 굵기의 작은 아이콘과 글자.
  장식 아이콘은 접근성 트리에서 제외한다. 환자 상태를 평가하는 삽화는 사용하지 않는다.
- 움직임: 선택·버튼 피드백 120~180ms. 이동량은 작게 하고 reduced-motion 설정에서는 제거한다.
- 얇은 선과 면을 섞어 구획을 만든다. 모든 문단을 개별 카드로 감싸지 않는다.

## 4. 화면 구성

### 4.1 첫 방문

상단에는 현재 APP_NAME 상수를 사용한다. 이름 변경은 이번 작업에 포함하지 않는다.
헤드라인은 '집에서의 관찰을, 다음 진료의 질문으로'를 사용하고 대상과 사용 방법을 짧게 설명한다.
주 버튼은 '관찰 기록 시작하기', 보조 동선은 '먼저 둘러보기'와 '기존 기록 이어받기'로 구분한다.

이용 방법은 '관찰 남기기 → 질문 준비하기 → 진료실에서 함께 보기'의 세 단계로 보여준다.
랜딩의 노트 미리보기에는 '예시'를 명시하고 실제 기록처럼 보이는 개인 정보나 건강 평가를 넣지 않는다.
모바일은 한 열, 넓은 화면은 소개와 노트 미리보기 두 열로 구성한다.

### 4.2 보호자 홈

상단: 서비스 이름과 글자 라벨이 있는 설정 진입. 그 아래 상태에 맞는 핵심 노트 한 개.

| 현재 상태 | 가장 눈에 띄는 내용·행동 |
| --- | --- |
| 이번 주 미기록 | 이번 주 관찰 안내와 기록하기 버튼. 전체 재확인 주는 항목 수 안내 유지 |
| 미기록 + 가까운 진료 | 기록하기가 주 행동. 진료 날짜와 준비 카드 링크는 그 아래 표시 |
| 기록 완료 + 가까운 진료 | 진료 날짜와 준비 카드 보기 버튼. 기록 완료는 보조 표시 |
| 기록 완료 + 변화 있음 | 기록 완료 안내 다음에 '지켜보고 있는 변화' 노트 |
| 기록 완료 + 변화 없음 | 서버 기준의 중립 문구와 기록 완료 표시, 전체 기록·공유 진입 |

이어서 다음 진료 정보, 관찰 변화, 전체 기록·공유 동선을 배치한다. 진료가 가까워 상단에
날짜가 표시된 경우 하단에 중복하지 않는다. 없는 날짜·없는 질문은 자리만 남기지 않는다.
질문 개수는 실제 응답에서 읽고, 0개인 경우 서버의 빈 상태 문구를 사용한다.

관찰 변화는 한 노트 안의 행으로 묶는다. 항목 이름 → 이전 표현과 현재 표현 → 유지 기간 순서다.
화살표는 두 표현 사이의 전환에만 사용하고 상승·하락 그래프로 표현하지 않는다.
확인 필요 등 서버 안내가 있는 경우 내용이 접히거나 축약되어 사라지지 않게 한다.

다음 기록의 정확한 날짜는 현재 Me 응답에 없으므로 임의 계산하지 않는다.
기록 완료 상태에서는 '이번 주 기록을 남겼습니다'와 현재 주차를 사용한다.

### 4.3 온보딩·주간 기록

한 화면에 한 가지 질문을 유지한다. 상단은 뒤로, 단계 이름, 현재 위치를 포함한다.
조건에 따라 바뀌는 전체 질문 수를 고정해 약속하지 않는다. 온보딩은 기본 정보·생활 관찰·마무리
구간을 구분하고, 관찰 구간은 카탈로그 기준의 항목 수를 보여준다. 하위 질문은 해당 항목에 포함한다.
주간 기록은 기존 상태 계산에서 나온 현재 흐름을 사용하며 분기 때문에 분모가 바뀌면 남은 단계도 갱신한다.

질문 영역은 넓은 여백과 큰 제목, 선택 영역은 흰색 면과 명확한 선택 표식을 사용한다.
선택한 답에는 체크와 테두리를 표시하고, 항목을 고른 직후 자동으로 다음 화면으로 넘기지 않는다.
조건부 질문은 같은 화면 아래에 열리며 키보드와 화면 읽기 도구로 순서대로 접근할 수 있다.

하단 다음 버튼은 작은 화면에서도 찾기 쉽게 sticky 영역에 둔다. 충분한 아래 여백과 safe-area를
확보해 마지막 선택지·오류·키보드가 열린 입력 칸을 가리지 않게 한다.
초안 복원, 뒤로 이동 시 답 유지, 저장 중 중복 제출 방지, 주차 변경 처리를 유지한다.

### 4.4 진료 준비 카드

상단에 날짜와 화면 제목을 두고, 질문을 순번이 있는 노트 면으로 보여준다.
각 질문은 20~22px로 읽기 쉽게 표시하며 같은 면 안에 '이 질문의 관찰 근거' 펼치기를 둔다.
질문 순번은 판정 우선순위가 아닌 목록 순서로만 표현한다.
추가 질문 입력은 별도 섹션으로 구분하고 기존 최대 5개·각 200자 제한을 유지한다.
편집 중에는 저장 버튼과 저장 상태를 분명히 표시한다. 실패하면 입력을 유지하고 재시도를 제공한다.
공유는 편집 중 저장 행동과 경쟁하지 않는 보조 동선으로 둔다.

### 4.5 전체 기록·치료사 보기

최신 수정의 가로 스크롤과 고정 항목 열을 유지한다. 모바일에서는 '좌우로 밀어 주차별 기록을 볼 수 있어요'
안내를 제공하고, 키보드로도 표 영역을 이동할 수 있게 한다.
주차별 데이터, 미기록, 지난 값 유지, 직접 확인의 구별을 글자와 범례로 전달한다.
지난 값 유지 표시는 과도하게 흐린 글자에 의존하지 않는다. 모든 값이 읽을 수 있는 대비를 갖는다.

보호자 기록은 앱의 노트 스타일을 적용한다. 치료사 화면은 정보를 빠르게 훑는 문서 스타일로
표 제목·기간·출처를 정돈하고, 인쇄에서는 흰 배경·그림자 제거·표 전체 표시를 적용한다.
치료사 화면의 토큰 처리, 제3자 리소스 차단, API와 요약 비캐시 규칙을 유지한다.

### 4.6 설정·이어받기·오류

설정은 '다음 진료', '가족과 기록 이어가기', '기록 알림'으로 묶는다.
현재 코드 확인·복사와 새 코드 발급은 의미와 결과를 설명한 별도 동작으로 둔다.
복구 폼의 라벨, 오류 시 수정할 항목, 홈으로 돌아가는 경로를 선명하게 보여준다.
404·잘못된 공유 링크는 같은 시각 언어를 적용하되 서로 다른 오류 설명을 유지한다.

## 5. 공통 상태와 접근성

- 로딩 중에도 서비스 이름과 화면 틀을 유지하고, 상태 문구가 있는 작은 로딩 영역을 제공한다.
  화면 전체를 빈 회색 블록으로 채우지 않는다. 요청 실패를 무한 로딩으로 보여주지 않는다.
- 저장 완료·복사 완료는 해당 조작 근처의 텍스트와 라이브 영역으로 알린다.
- 실패 시 가능한 재시도와 돌아가기 행동을 제시하며 이미 입력한 값은 보존한다.
- 페이지마다 h1, 주요 구획 h2를 제공한다. 입력 이름, 펼치기 상태, 선택 상태를 유지한다.
- 라우트·질문 단계 전환 시 새 제목으로 포커스를 옮기되 입력 중에는 포커스를 빼앗지 않는다.
- 200% 글자 확대, 320px 화면, 긴 질문, 5개 추가 질문에서도 잘리지 않는다.
- 선택 배경을 제거한 흑백 화면에서도 체크·선·문구로 상태를 이해할 수 있어야 한다.

## 6. 구현 구조와 데이터

기존 React·Tailwind·React Query 구조에서 프론트 표시 계층을 개선한다.
styles.css에 역할 기반 토큰을 두고 Button·Choice·Screen·Notice·Collapse를 우선 정리한다.
페이지 헤더, 노트 면, 로딩·오류 상태, 조작 행은 여러 화면에서 실제로 공유될 때 작은 컴포넌트로 추출한다.
홈의 상태 계산은 기존 lib/home.ts와 queries를 재사용한다. 디자인 요소가 API 요청이나 판정을 하지 않게 한다.
각 화면은 데이터 상태에 맞는 표현을 선택하며, 서버 문장과 질문 근거의 연결을 그대로 유지한다.
동일 출처의 로컬 아이콘과 시스템 글꼴을 사용한다. 별도 디자인 프레임워크나 외부 이미지 서비스는 추가하지 않는다.

## 7. 범위와 검증 기준

대상은 랜딩, 홈, 온보딩, 주간 기록, 준비 카드, 전체 기록, 설정, 이어받기, 치료사 보기, 오류·로딩 상태다.
탭 바·계정·건강 지표·운동 추천 등 신규 제품 기능은 이번 개선에 포함하지 않는다.

완료 기준:

1. 미기록·기록 완료·가까운 진료·변화 없음 상태별 주 행동이 일관된다.
2. 입력 진행·선택·완료·오류를 색 없이도 구분할 수 있다.
3. 최신 QA 수정 및 기존 입력·복구·공유·근거 표시 회귀 테스트가 통과한다.
4. 새 상태 처리와 포커스 동작은 행동 중심 테스트로 확인한다. CSS 값만 복제하는 테스트는 만들지 않는다.
5. typecheck, 기존 단위·화면 테스트, production build를 통과한다.
6. 375px·768px·1280px에서 주요 흐름을 실제 렌더링으로 검증하고 320px·200% 확대를 확인한다.
7. 표의 첫 주·마지막 주 접근, 인쇄, 긴 질문, 키보드 입력 시 하단 버튼 가림을 확인한다.
8. 랜딩·홈·기록 입력·준비 카드의 변경 전후 화면을 같은 조건으로 비교해 결과를 보고한다.

검토 후 구현 계획은 공통 디자인 → 홈·랜딩 → 입력 흐름 → 읽기·설정 화면 → 전체 검증 순서로 작성한다.
