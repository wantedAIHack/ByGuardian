승인일 2026-09-06. README v3가 제품 스펙이고, 이 문서는 그 §9(화면)를 React PWA로 옮기는 계약이다.

백엔드(`backend/engine`, `backend/api`)는 완료돼 있다. API 계약은 `2026-09-05-api-design.md`.

## 0. 이 설계를 만든 결정들

브레인스토밍에서 확정된 것. 되돌리려면 여기부터 읽는다.

| 결정 | 선택 | 이유 |
| --- | --- | --- |
| 온보딩 분량 | **기준선 8항목을 온보딩에서 전부 받는다** | 평생 한 번이고, 그 뒤 매주는 버튼 하나 20초. 뒤로 미루면 백엔드를 다시 열어야 하고 축이 나중에 들어오면 궤적에 결측이 생긴다 |
| 계정 | **없음. 기기 토큰 유지** | 카카오 OAuth는 기기 분실을 풀지만 "사용자가 누구인지도 모른다"는 §8의 개인정보 카드를 약화시킨다. 예선 통과 후 알림톡과 함께 재검토 |
| 기기 분실 대비 | **복구 코드 재발급 + 두 번째 보호자 권유** | 해시만 저장하므로 기존 코드를 되살릴 수 없다. 재발급이 유일한 길. 두 번째 보호자는 이미 되는 기능이고 작성자 구분까지 얻는다 |
| 주간 알림 | **메인 화면 상태 + 캘린더 반복 일정(.ics)** | 브라우저 푸시는 iOS에서 홈 화면 설치를 요구해 대상 사용자 절반이 못 받는다. 스토어 앱은 개발자 계정이 없고 플레이의 14일 테스트 요구가 마감과 충돌한다 |
| 음성 입력 | **직접 구현하지 않는다. 폰 키보드 받아쓰기** | 대상 사용자에게 더 익숙하고, iOS 편차가 없고, 음성이 제3자로 나가는 것이 우리 제품의 행위가 아니게 된다 |
| 화면 구조 | **탭 바 없음. 홈 한 화면 + 전체 화면 흐름** | 탭 넷은 앱을 열자마자 네 개의 선택을 던진다. 매주 하는 일은 하나뿐이다 |

**범위 밖.** 브라우저 푸시, 카카오 로그인, 스토어 배포, 오프라인 쓰기 큐, 다국어.

## 1. 설계 원칙

이 앱의 사용자는 **노인을 돌보는 40~70대 보호자**다. 피곤하고, 한 손으로 폰을 들고, 하루 중 짬이 날 때 3분 쓴다. 앱 사용에 익숙하지 않을 수 있다.

1. **어느 순간에든 눈에 띄는 행동이 정확히 하나다.** 그 버튼에 동사가 들어간다.
2. **해석이 필요한 숫자를 화면에 두지 않는다.** 점수·퍼센트·그래프·게이지 없음. §2가 금지하기도 하고, §부록의 "저희는 측정하지 않습니다"가 무너지기 때문이다.
3. **좋고 나쁨을 색으로 말하지 않는다.** 초록·빨강은 그 자체가 판정이다.
4. **아이콘 단독으로 뜻을 전달하지 않는다.** 항상 글자를 붙인다.
5. **비어 있는 화면을 부끄러워하지 않는다.** 침묵 상태가 기본이고 데모의 핵심 장면이다.
6. **한국어를 하드코딩하지 않는다.** 관찰 항목·축·라벨은 전부 `/catalog`에서 온다.

## 2. 정보 구조

탭 바 없음. 홈이 유일한 착지점이고, 나머지는 홈에서 들어가거나 전체 화면을 덮는다.

```
/                 홈 (상태 5가지)
/onboarding       전체 화면 흐름 — 온보딩
/record           전체 화면 흐름 — 주간 기록
/trajectory       전체 궤적 (읽기)
/prep-card        진료 준비 카드 (읽기 + 추가 질문 편집)
/settings         복구 코드 재발급, 두 번째 보호자 초대, 알림, 외래일 수정
/recover          복구 코드로 이어받기 (새 기기 진입점)
/t/:token         치료사용 요약 (인증 없음, 별도 레이아웃)
/demo             데모 케이스 생성 후 홈으로
```

`/t/:token`은 보호자용 껍데기(헤더·하단)를 쓰지 않는다. 치료사가 처음 보는 화면이고 인쇄 대상이다.

## 3. 홈 — 상태 다섯

홈은 세로 한 줄기다. 위에서부터 **행동 → 경과 → 조용한 목록** 순이다.

### 상태 A — 온보딩 전

```
[제품 이름]

집에서 보신 것을 남겨두시면,
다음에 병원 가실 때 여쭤볼 것을 만들어 드립니다.

        [ 시작하기 ]

    이미 쓰고 계신가요? 이어받기
```

"이어받기"가 `/recover`로 간다. 작게 둔다.

`/recover`는 **복구 코드와 관계를 함께** 받는다(`POST /guardians/recover`가 둘 다 요구한다). 화면 문구는 "어떤 분이신가요?"로, 딸·아들·배우자 같은 선택지를 온보딩과 같은 모양으로 낸다. 이 답이 그대로 작성자 라벨이 되어 치료사용 요약의 작성자 변경 표시에 쓰인다. 코드가 틀리면 404가 오고, "코드를 다시 확인해 주세요"로 보여준다.

### 상태 B — 이번 주 기록 안 함

```
이번 주 관찰을 남겨주세요
6주차 · 3분이면 됩니다

     [ 3분 기록하기 ]
```

`GET /me`의 `fullRecheck`가 참이면 부제가 **"이번 주는 8가지를 모두 여쭤봅니다"**로 바뀐다. 놀라지 않게 미리 알린다.

### 상태 C — 기록함, 변화 없음 (침묵)

```
이번 주 기록을 남기셨어요 ✓

이번 기간에는 바뀐 항목이 없습니다.

(여백)
```

**여백을 채우지 않는다.** 여기에 무엇이든 넣고 싶은 충동이 이 제품을 망친다.

### 상태 D — 기록함, 변화 있음

```
이번 주 기록을 남기셨어요 ✓

지켜보고 있는 변화

  화장실 이용
  지켜보면 됨 → 혼자 하심
  이 변화가 4주째 유지되고 있습니다.

  집 안에서 걷기 · 보조 도구
  워커 → 지팡이
  이 변화가 2주째 유지되고 있습니다.
```

`GET /me/progress`의 `changes`를 그대로 쓴다. 문장은 서버가 만든 `message`를 그대로 보여준다. **프론트에서 문장을 만들지 않는다.**
`transitions`가 있으면 목록 위에 회색 안내 한 줄로 둔다.

### 상태 E — 외래 3일 이내

준비 카드 블록이 맨 위로 올라온다.

```
9월 8일 진료가 있습니다 (모레)

여쭤볼 것 2가지를 준비했습니다.

     [ 진료 준비 카드 보기 ]
```

**개수를 고정하지 않는다.** `GET /me/prep-card`의 `questions`는 최대 3개이고 0개일 수 있다.
개수는 그 배열의 길이를 그대로 쓴다. 0개면 문장을 서버의 `emptyMessage`로 갈아끼운다.
"3가지를 준비했습니다"를 상수로 박으면 조용한 주에 앱이 없는 것을 있다고 말하게 된다. §2 위반이다.

질문 문장 자체는 홈에 노출하지 않는다. 카드에서 근거와 함께 봐야 뜻이 산다.

### 홈 아래 — 조용한 목록

상태와 무관하게 항상 아래에 둔다. 작은 글씨, 강조 없음.

- 다음 진료 · 9월 8일 (외래일이 있을 때만)
- 지금까지 6주 중 5주 기록
- 전체 기록 보기 → `/trajectory`
- 치료사에게 보여드리기 → 링크 발급
- 설정 → `/settings`

## 4. 온보딩 (`/onboarding`)

README §9 화면 1. **한 화면에 한 가지만 묻는다.** 상단에 진행 막대.

```
0  안내       "5분 정도 걸립니다. 8가지를 여쭤봅니다."   [시작]
1  관계       딸 / 아들 / 배우자 / 며느리 / 사위 / 기타(직접 입력)
2  진단명     뇌졸중 / 그 밖 / 모름          ← 모름이 기본값
3  마비 쪽    왼쪽 / 오른쪽 / 없음 / 모름
4  표현       "말씀으로 불편한 곳을 알려주시나요?"  잘 하심 / 가끔 어려움 / 거의 어려움
5  외래일     날짜 선택 (건너뛰기 가능)
6  기준선 안내 "지금 상태를 8가지로 한 번 여쭤보겠습니다."
7~14 기준선   항목 하나당 한 화면
15 복구 코드  코드 표시 + [적어뒀습니다] 필수
16 두 번째    "다른 가족도 함께 기록하시겠어요?"
17 알림       "매주 알림을 받으시겠어요?" → .ics 내려받기
```

### 기준선 한 화면의 모양

```
    화장실 이용                     (7 / 14)
    ▓▓▓▓▓▓▓░░░░░░░

    요즘 어떠신가요?

    [그림] 혼자 하심
    [그림] 지켜보면 됨
    [그림] 손 잡아드림
    [그림] 대부분 도움
```

- 4단계는 세로로 큰 카드 넷. 그림 + 글자. 그림만으로 뜻을 전달하지 않는다.
- 그 항목에 적용되는 축(보조 도구·일관성·마비 쪽 손)은 **도움 수준을 고른 뒤 같은 화면 아래에 나타난다.** 처음부터 다 보이면 화면이 무겁다.
- `hand` 축은 마비 쪽이 왼쪽·오른쪽일 때만 나타난다. `/catalog`의 `axes`와 온보딩 3단계 답으로 결정한다.
- 뒤로 가기 가능. 앞선 답은 유지한다.

### 온보딩 선택지가 보내는 값

화면의 한국어는 `/catalog`에 없다. 카탈로그는 관찰 항목·축·신호·시간대·수면 라벨만 준다.
아래 세 가지는 프론트 상수이고, **API는 열거값만 받는다.** 한국어를 그대로 보내면 400이다.

| 화면 | 보이는 글자 | 보내는 값 |
| --- | --- | --- |
| 2 진단명 | 뇌졸중 / 그 밖 / 모름 | `STROKE` / `OTHER` / `UNKNOWN` |
| 3 마비 쪽 | 왼쪽 / 오른쪽 / 없음 / 모름 | `LEFT` / `RIGHT` / `NONE` / `UNKNOWN` |
| 4 표현 | 잘 하심 / 가끔 어려움 / 거의 어려움 | `NONE` / `SOMETIMES` / `OFTEN` |

4번 표를 특히 조심한다. **"잘 하심"이 `NONE`이다.** 어려움의 정도를 세는 값이라 화면 순서와 이름이 반대로 읽힌다.
여기를 뒤집으면 서버가 `signalsEnabled`를 반대로 잡고, 통증 신호 관찰이 필요 없는 케이스에 켜지거나
정작 필요한 케이스에서 꺼진다. 조용히 틀리는 자리이므로 테스트로 고정한다.

### 중간에 나가도 잃지 않는다

온보딩은 화면이 열일곱 개인데 `POST /cases` 전에는 `caseId`도 토큰도 없다.
`localStorage`의 `draft:onboarding` 한 키에 단계와 답을 담고, 앱을 다시 열면 그 단계로 돌아간다.
`POST /cases`가 성공하면 지운다. **전화 한 통에 처음부터 다시 하게 두지 않는다.**
복구 코드 화면(15) 이후로는 초안을 쓰지 않는다. 케이스가 이미 만들어졌기 때문이다.

### 그림이 없으면 글자로 간다

4단계 카드의 그림은 **없어도 출시된다.** 큰 글자 카드가 기본이고 그림은 그 위에 얹는 것이다.
그림 없이 먼저 만들고, 시간이 남으면 넣는다. 마감이 9월 20일이라 삽화 제작을 임계 경로에 두지 않는다.

### 온보딩이 보내는 것

`POST /cases` 한 번. **통증 신호를 온보딩에서 묻지 않는다.** 표현이 어려운 케이스라도 기준선의 `painSignal`은 `{}`로 보낸다. 신호는 "이번 주에 무엇을 봤는가"라는 주간 관찰이고, 기준선은 "지금 어떤 상태인가"라서 성격이 다르다. 엔진의 데모 시드도 1주차를 빈 집합으로 둔다.

API는 비언어 관찰이 활성인 케이스에 `painSignal`이 `null`이면 400을 낸다. 활성이면 `{}`, 비활성이면 `null`을 보낸다. `sleep`과 `freeNote`는 온보딩에서 묻지 않으므로 `null`.

### 복구 코드 화면

```
    이어받기 코드

        K7M3P9RW

    폰을 바꾸거나 앱을 지우면
    이 코드로 기록을 되찾습니다.

    지금 적어두시거나 사진을 찍어두세요.
    다시 보여드릴 수 없습니다.

    [ 적어뒀습니다 ]     ← 누르기 전에는 못 넘어감
```

"다시 보여드릴 수 없습니다"는 사실이다. 서버가 해시만 갖고 있다.

## 5. 주간 기록 (`/record`)

README §9 화면 2의 분기 그대로. 전체 화면. 중간에 나가도 기기에 임시 저장하고 이어서 한다.

```
1  "지난주와 달라진 게 있나요?"
       [ 네, 달라진 게 있어요 ]     [ 없어요 ]

2  (네를 고른 경우) 달라진 항목 고르기 — 8개 중 다중 선택
3  (고른 항목만) 항목당 한 화면. 도움 수준 + 적용 축 + 한 줄 기록
4  통증 신호 — 온보딩에서 활성화됐으면 매주 필수. 1단계에서 "없어요"를 눌러도 묻는다
5  야간 수면 — 3단계. 1단계에서 "없어요"를 눌러도 매주 묻는다
6  기타 자유 기록 + 시간대
7  저장 → 홈으로
```

- **수면을 빠뜨리지 않는다.** `PUT /me/weeks/{week}`의 `sleep`, `/catalog`의 `sleepLevels`, 치료사용 요약의 `sleep`이 모두 이미 있다. 여기서 안 물으면 그 셋이 영원히 빈다. 라벨은 카탈로그에서 온다.
- **전체 재확인 주(4의 배수)** 는 1단계를 건너뛰고 바로 8항목을 순서대로 묻는다. 시작 전에 **"이번 주는 8가지를 모두 여쭤봅니다"**를 보여준다.
- 전체 재확인 화면은 **지난달 답을 함께 보여준다**(README §9). `GET /me/trajectory`에서 직전 값을 읽어 항목 화면 아래에 회색 한 줄로 둔다. 앵커링 위험은 README가 이미 저울질해 두었다.
- 통증 신호 화면은 동작별로 묻는다. **"없었어요"가 큰 버튼으로 먼저 있고**, 그게 `painSignal: {}`로 나간다.
- 자유 기록 칸은 처음부터 여러 줄. 라벨은 **"말씀하시듯 편하게 적어주세요"**. 첫 사용 때 한 번만 **"키보드의 마이크를 누르면 말로 적을 수 있어요"** 안내를 띄운다.
- 저장은 `PUT /me/weeks/{week}` 한 번. `week`는 `GET /me`가 준 값을 그대로 쓴다.
- 409 `WEEK_MISMATCH`는 **말없이 재시도하지 않는다.** 자정을 넘겨 저장을 누른 경우다.
  그대로 재시도하면 지난주에 본 것이 이번 주 기록이 된다. 층 1은 버리지도 않지만 옮기지도 않는다.
  `/me`를 다시 받고 **화면에 물어본다.** "날짜가 바뀌었습니다. 방금 적으신 내용은 지난주 것인가요, 이번 주 것인가요?"
  이번 주로 답하면 새 주차로 보내고, 지난주 것이면 초안을 지우고 홈으로 보낸다(지난 주차는 이미 닫혔다).
  새 주차가 **전체 재확인 주면 부분 payload가 400을 받는다**(`SnapshotService`가 8항목을 전부 요구한다).
  그 경우 재시도하지 말고 전체 재확인 흐름을 처음부터 연다.

### 임시 저장

`localStorage`에 `draft:{caseId}:{week}` 키로 단계와 입력을 담는다. 저장 성공 시 지운다.
주차가 바뀌었다고 초안을 조용히 버리지 않는다. 위의 `WEEK_MISMATCH` 물음을 거친 뒤에 지운다.

## 7. 진료 준비 카드 (`/prep-card`)

`GET /me/prep-card`. README §9 화면 4.

```
9월 8일 진료

1. 화장실 이용은 혼자 하심으로 바뀌셨는데
   집 안에서 걷기는 6주째 그대로입니다.
   집 안에서 걷기는 왜 안 늘고 있을까요?

   [ 근거 보기 ]  → 접힌 궤적

2. ...

내가 더 여쭤보고 싶은 것
   [+ 추가]
```

- 질문은 최대 3개. 없으면 `emptyMessage`를 그대로 보여준다. **빈 칸을 만들지 않는다.**
- 근거는 기본 접힘. `evidence.items`의 궤적과 `evidence.signal`의 주차를 보여준다.
- 추가 질문은 `PUT /me/prep-card/extra`. 최대 5개, 각 200자.
- 하단에 `therapistGlance`를 **"진료실에서 보여드릴 요약"**으로 두고 링크 발급 버튼을 붙인다.

## 8. 치료사용 요약 (`/t/:token`)

`GET /t/{token}`. 인증 없음. README §9 화면 5.

**보호자용 껍데기를 쓰지 않는다.** 헤더도 하단 목록도 없다. 인쇄 대상이다.
**한 장에 다 넣겠다고 약속하지 않는다.** 자유 기록은 주당 500자까지 들어올 수 있어서 분량이 기록량에 비례한다.
대신 순서를 지킨다. 위에서부터 궤적·신호·수면이 먼저 오고, 자유 기록이 뒤로 간다.
치료사가 첫 화면에서 표를 보고, 필요하면 아래로 내려 원문을 읽는다.

- 주차별 궤적 표. 항목 아래 축이 부속 행. 변화 없는 항목은 한 줄로 접는다
- 비언어 신호를 주차별 점으로: `· ● ● · ● ●`
- 야간 수면 주차별 값 (`sleep`)
- 자유 기록 **원문 그대로**, 시간대 라벨과 함께
- 보호자가 묻고 싶은 것
- 기록 밀도와 작성자, 작성자 변경 지점
- 하단 한계 문단(`disclaimer`)

**판정 문구를 절대 덧붙이지 않는다.** 서버가 판정 필드를 주지 않으므로 프론트가 만들어낼 수도 없다. "좋아졌습니다" 같은 요약을 넣고 싶은 충동이 생기면 §2를 읽는다.

인쇄용 CSS를 따로 둔다. 화면에서는 가로 스크롤, 인쇄에서는 축소.

## 9. 설정 (`/settings`)

- **다른 가족 초대하기** — **지금 있는 복구 코드를 그대로 알려주는 흐름이다.** 새로 만들지 않는다.
  받은 사람이 `/recover`에서 코드와 자기 관계를 넣으면 같은 케이스에 자기 토큰이 생긴다(`POST /guardians/recover`).
  여기서 코드를 재발급하면 온보딩 때 적어두게 한 그 코드가 죽는다. **초대는 재발급이 아니다.**
- **복구 코드 다시 만들기** — 적어둔 종이를 잃은 경우에만 쓴다. 폰에 토큰이 남아 있어야 부를 수 있다.
  누르면 확인 후 새 코드 발급, **옛 코드와 그것으로 초대한 사람의 초대 경로가 함께 죽는다**는 것을 먼저 알린다
- **주간 알림** — .ics 다시 내려받기
- **다음 진료일 바꾸기** — `PATCH /me`
- **치료사 링크** — 새로 만들면 옛 링크가 죽는다는 안내

## 10. 기술

| 항목 | 선택 |
| --- | --- |
| 빌드 | Vite + React 19 + TypeScript. Node 22 (`.nvmrc`) |
| 스타일 | Tailwind. 토큰은 CSS 변수 한 벌 |
| 라우팅 | react-router |
| 서버 상태 | TanStack Query |
| PWA | vite-plugin-pwa (홈 화면 설치 가능. 푸시는 안 씀) |
| 테스트 | Vitest + Testing Library. 흐름 테스트는 MSW로 API 목 |

### 데이터 규칙

- 앱 시작 시 `GET /catalog` 1회, 오래 캐시. **관찰 항목·축·신호·시간대·수면 라벨이 여기서 온다.** 온보딩의 관계·진단명·마비 쪽·표현 선택지와 버튼·안내 문구는 카탈로그에 없다. 프론트 상수다(§4의 매핑 표).
- 토큰은 `localStorage`의 `guardianToken`. 모든 `/me` 요청 헤더에 붙인다. 401이면 `/recover`로 보낸다.
- 서버가 만든 문장(`message`, `sentence`, `emptyMessage`, `disclaimer`)은 **그대로 렌더**한다. 자르거나 덧붙이지 않는다.
- 오류는 `{code, message}` 한 가지 모양. 409 `WEEK_MISMATCH`만 특별 처리(주차 갱신 후 재시도), 나머지는 메시지를 그대로 보여준다.

### 디자인 토큰

- 본문 17px, 버튼 글자 18px, 제목 22~28px. 터치 영역 최소 48px
- 색: 중성 회색 계열 + 강조 1색. **의미색(초록/빨강) 없음**
- 간격 4px 배수. 화면 좌우 여백 20px
- 라이트 모드만. 다크 모드는 범위 밖

## 12. 코덱스 리뷰로 고친 것 (2026-09-06)

독립 리뷰가 짚어 실제 코드에 대조해 확인한 결함들이다.

| 무엇 | 왜 문제였나 |
| --- | --- |
| 수면을 아무 데서도 안 물었다 | `PUT /me/weeks/{week}.sleep`, `/catalog.sleepLevels`, `TherapistSummaryDto.sleep`, README §5가 다 있는데 화면이 없었다. 제품 항목 하나가 통째로 빠질 뻔했다 |
| 홈이 "3가지"를 상수로 박았다 | `questions`는 0~3개다. 조용한 주에 없는 것을 있다고 말한다. §2 위반 |
| 초대가 복구 코드를 재발급했다 | `/guardians/recover`는 **지금 있는** 코드를 받는다. 재발급하면 온보딩에서 적어두게 한 코드가 죽는다 |
| 전체 재확인에 지난달 답이 없었다 | README §9가 보여주라고 한다 |
| 온보딩 열거값 매핑이 없었다 | 한국어를 보내면 400이다. 특히 표현 4단계는 "잘 하심"이 `NONE`이라 뒤집기 쉽다 |
| 온보딩에 초안이 없었다 | 화면 열일곱 개인데 `caseId`가 생기기 전이라 중간에 나가면 전부 잃는다 |
| `WEEK_MISMATCH`를 그냥 재시도했다 | 지난주 관찰이 이번 주 기록이 된다. 새 주차가 재확인 주면 400도 난다 |
| 카탈로그가 모든 라벨을 준다고 썼다 | 관찰 쪽 라벨만 준다. 온보딩 선택지는 없다 |
| A4 위쪽 3분의 1을 약속했다 | 자유 기록이 주당 500자다. 분량이 기록량에 비례한다 |

받았지만 반영하지 않은 지적: `.ics`·PWA·React 19를 잘라내라는 제안. 알림 수단이 `.ics` 하나뿐이라 자르면 주간 알림이 사라지고,
나머지 둘은 설정 몇 줄이라 위험이 아니다. 하단 조용한 목록이 이미 부차 기능을 다 담고 있어 탭 바 부재도 문제가 아니다.

## 13. 결정 기록

- **탭 바 없음** — 매주 하는 일이 하나뿐이다. 뒤집으려면 홈이 감당 못 할 만큼 기능이 늘었을 때.
- **의미색 없음** — 색으로 좋고 나쁨을 말하는 순간 §2 위반이다.
- **문장은 전부 서버가 만든다** — 프론트가 한국어를 조립하기 시작하면 §2 검증이 두 곳으로 흩어진다.
- **라이트 모드만** — 마감.
- **오프라인 쓰기 큐 없음** — 초안 임시 저장까지만. 전송 실패는 사용자에게 보여주고 재시도하게 한다.
