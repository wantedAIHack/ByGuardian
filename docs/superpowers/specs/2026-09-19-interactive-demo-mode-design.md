# Interactive Demo Mode Design

## Goal

해커톤 심사위원과 사용자가 실제 서비스와 같은 온보딩, 기준선 기록, 주간 기록, 변화 감지, 진료 준비, 치료사 공유 흐름을 짧은 시간 안에 직접 체험할 수 있게 한다. 일반 사용자 케이스의 날짜와 기록 규칙은 바꾸지 않는다.

## User flow

1. 랜딩의 `먼저 둘러보기`로 `/demo`에 진입한다.
2. 데모 안내에서 `온보딩부터 시작하기`를 누른다.
3. 일반 사용자와 같은 온보딩 전체를 진행하고 다음 진료일을 직접 선택하거나 건너뛴다.
4. 마지막 기준선 저장은 데모 전용 생성 API로 전송된다. 결과는 1주차 기록이다.
5. 데모 케이스가 활성화되면 보호자 화면 상단에 `데모 모드`, 가상 오늘 날짜, 현재 주차를 항상 표시한다.
6. 현재 주차 기록이 있으면 `다음 주차로 이동`을 눌러 가상 날짜를 7일 진행한다.
7. 새 주차의 기록을 남기고 다시 진행한다. 4의 배수 주차에는 기존 규칙대로 전체 재확인을 한다.
8. 선택한 진료일이 가까워지면 기존 진료 준비 카드가 나타나며, 치료사 공유 링크와 리포트도 실제 API 데이터를 사용한다.
9. `데모 종료`를 누르면 세션의 데모 토큰과 데모 초안을 지우고 랜딩으로 돌아간다. 같은 브라우저에 일반 사용자 토큰이 있었다면 보존한다.

## Data model and time boundary

`cases`에 다음 열을 추가한다.

- `demo_mode boolean not null default false`
- `demo_today date null`

일반 케이스는 `demo_mode=false`, `demo_today=null`이다. 데모 케이스는 `demo_mode=true`이며 생성 당시 서울 기준 오늘을 `demo_today`에 저장한다. 데이터베이스 제약으로 두 필드의 조합을 검증한다.

`CaseTimeline`이 케이스별 시간의 유일한 진입점이 된다.

- `today(CaseEntity)`: 일반 케이스는 실제 Clock, 데모 케이스는 `demo_today`
- `currentWeek(CaseEntity)`: 케이스 시작일과 위 날짜로 계산

`CaseService`, `SnapshotService`, `ProgressService`, `PrepCardService`, `TherapistSummaryService`는 직접 `WeekCalculator.currentWeek(startDate)`를 호출하지 않고 `CaseTimeline`을 사용한다. `WeekCalculator`는 실제 오늘과 날짜 간 주차 계산이라는 순수한 책임을 유지한다.

## API

### `POST /demo/cases`

일반 `OnboardingRequest`를 그대로 받는다. 일반 온보딩과 같은 검증 및 기준선 조립을 수행하되 데모 플래그와 가상 오늘을 저장한다. `OnboardingResponse` 형식도 동일하다.

기존 `POST /demo`의 6주 시드 생성 계약은 제거한다. 엔진 검증용 `DemoSeed`는 테스트 자료로 유지할 수 있지만 공개 데모 진입점에서는 사용하지 않는다.

### `POST /me/demo/advance`

인증된 현재 케이스가 데모 케이스이고 현재 주차 스냅샷이 저장된 경우에만 `demo_today`를 7일 증가시킨다. 케이스 행을 쓰기 잠금으로 읽어 중복 클릭이 날짜를 14일 진행시키지 않게 한다. 응답은 갱신된 `MeResponse`다.

오류 코드는 다음과 같다.

- 일반 케이스: `DEMO_ONLY` 409
- 현재 주차 미기록: `DEMO_WEEK_NOT_RECORDED` 409

`MeResponse`에는 `demoMode`와 `canAdvanceDemo`를 추가한다. `today`는 데모에서 가상 오늘을 반환한다. 구형 프런트엔드와의 호환을 위해 새 필드는 추가만 한다.

## Visit dates

온보딩과 설정에서 다음 진료일은 해당 케이스의 오늘보다 과거일 수 없다. 데모 생성 시에는 실제 오늘이 곧 최초 가상 오늘이다. 데모 진행으로 가상 오늘이 진료일을 지나더라도 기존 값을 자동 변경하거나 삭제하지 않는다. 사용자가 이후 진료일을 수정할 때는 현재 가상 오늘 이후만 허용한다.

## Frontend isolation

`Onboarding`은 `mode: 'standard' | 'demo'` 속성을 받는다. 화면과 상태 전이는 공유하고 다음 부분만 모드별로 나눈다.

- 저장 URL: `/cases` 또는 `/demo/cases`
- 초안 키: 일반/데모 별도
- 성공 시 토큰 저장소: 일반은 `localStorage`, 데모는 `sessionStorage`
- 완료 뒤 이동: 동일하게 보호자 홈

API 인증 토큰은 세션의 데모 토큰을 우선하고, 없으면 기존 일반 토큰을 사용한다. 데모 종료와 데모 401은 데모 토큰만 제거한다. 따라서 데모 체험이 기기에 저장된 일반 기록을 덮어쓰지 않는다.

`DemoBanner`는 인증된 데모 세션에서 보호자용 `App` 상단에 표시한다. 가상 날짜, 현재 주차, `다음 주차로 이동`, `데모 종료`를 제공한다. 진행 중에는 버튼을 잠그고, 성공 시 `/me` 아래의 모든 React Query 캐시를 무효화한다. 현재 주차가 미기록이면 버튼을 비활성화하고 먼저 기록하라는 설명을 표시한다.

## Failure handling

- 데모 생성 실패 시 입력과 별도 데모 초안을 유지하고 같은 화면에서 재시도한다.
- 주차 진행 실패 시 현재 화면과 날짜를 유지하고 서버 오류 문구를 배너에 표시한다.
- 빠른 중복 클릭은 프런트엔드 동기 잠금과 서버 행 잠금으로 모두 방어한다.
- 새로고침해도 같은 탭에서는 `sessionStorage`의 데모 세션을 이어간다.
- 탭을 닫으면 데모 인증은 사라진다. 서버 데이터 자동 삭제는 이번 해커톤 범위에 포함하지 않는다.

## Analysis behavior

데모 기록은 기존 기록·변화 감지·질문 생성·리포트 파이프라인을 그대로 사용한다. 데모 전용 분석 규칙이나 자동 분석은 추가하지 않는다. 질문지 v2와 이전 질문지의 버전 경계 규칙도 그대로 유지한다.

## Verification

- 데이터베이스 마이그레이션과 일반/데모 케이스 불변식 테스트
- 일반 케이스가 실제 Clock을 유지하는 회귀 테스트
- 데모 온보딩이 1주차를 만들고 선택한 진료일을 보존하는 API 테스트
- 기록 전 진행 거부, 기록 후 정확히 7일 진행, 중복 진행 직렬화 테스트
- 가상 주차가 스냅샷 저장·진행·진료 준비·치료사 요약에 일관되게 반영되는 통합 테스트
- 일반 토큰 보존, 데모 세션 토큰 우선순위와 종료 테스트
- 기존 온보딩 UI 재사용 및 별도 초안 테스트
- 브라우저에서 온보딩 → 1주차 → 2주차 → 진료 준비/리포트까지 실제 API로 검증

## Non-goals

- 시스템 시계 또는 일반 케이스 날짜 변경
- 자유 날짜 이동, 이전 주차로 되돌리기, 기록 건너뛰기
- 데모 전용 분석 또는 LLM 동작
- 자동 만료·정리 스케줄러와 관리자 화면
- 미리 채워진 6주 시드 공개 데모
