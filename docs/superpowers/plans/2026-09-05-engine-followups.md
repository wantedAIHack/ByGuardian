# 규칙 엔진 후속 작업 — API 계획을 쓰기 전에 읽으세요

엔진(`backend/engine`)은 2026-09-05에 완료됐습니다. 커밋 13개, 테스트 92개, 전체 통과.
이 문서는 리뷰에서 나왔지만 엔진 범위 밖이라 넘긴 것들입니다. **API 계획의 첫 태스크가 이 문서를 반영해야 합니다.**

---

## 1. 지금 바로 고쳐야 하는 것 (문서 오류 1건)

리뷰 마지막 단계에서 발견됐고, 수정 물결이 이미 닫힌 뒤라 남겨뒀습니다.

**`WeeklyNote`의 Javadoc과 README §5의 자유 기록 절이 분모를 잘못 설명합니다.**

두 곳 다 "목록의 길이가 '4주 중 3주'의 4가 된다"는 취지로 쓰여 있습니다.
실제 분모는 `min(TIME_WINDOW_WEEKS, notes.size())`, 즉 **최대 4로 잘립니다**(`CrossDetector.timeOfDay`).
데모 시드는 목록이 6개인데 문장은 "4주 중"으로 나옵니다.

전달하려던 내용 자체는 맞습니다. 태그 없는 주도 목록에 남아 분모에 포함된다는 것.
틀린 건 "길이 = 분모"라는 등식뿐입니다. 두 문장만 고치면 됩니다.

## 2. 금지 어휘 목록의 나머지 절반 — 치료사 확인 필요

엔진의 `Templates.FORBIDDEN`은 현재 19개입니다. 전부 "좋아졌다·나빠졌다" 계열입니다.
README §2는 금지 사항을 다섯 갈래로 나열하는데, **목록은 그중 한 갈래만 막고 있습니다.**

최종 리뷰어가 실제로 통과시켜 본 문장들입니다.

| 문장 | 현재 필터 | §2 상태 |
| --- | --- | --- |
| 재활에 도움이 될까요? | 통과 | "재활"은 비의료기관 금지 용어 |
| 치료를 더 받으셔야 할까요? | 통과 | "치료"도 마찬가지 |
| 병원에 가보셔야 할까요? | 통과 | §2가 직접 예시로 든 금지 문구 |
| 낙상 점수가 올라갔을까요? | 통과 | 위험도·점수 산출 금지 |
| 운동을 더 하시면 어떨까요? | 통과 | 운동 처방 금지 |

**넣을 후보:** 재활, 치료, 병원, 낙상, 점수, 처방, 운동, 진단, 기능검사

**바로 넣지 않은 이유:** 과차단 위험이 있습니다. "병원에서는 어떠셨나요?" 같은 정상적인 질문까지 막힙니다.
어느 선까지 막을지는 치료사와 스펙의 판단이 필요합니다.
`TemplatesTest.everyTypeRendersSafeQuestion`이 그 검증 하네스입니다. 새 단어가 기존 템플릿과 충돌하면 빌드가 깨집니다.
(참고로 "치료"는 현재 카탈로그 어디에도 없습니다.)

**구조적 한계 하나 — 이건 고칠 게 아니라 발표에 넣을 것.**
부분 문자열 목록은 우회 표현을 못 잡습니다. "걷기가 늘지 않고 있습니다"는 물음표 규칙에만 걸립니다.
그걸 실제로 막는 건 §8 가드레일 3번, **2회 재생성 실패 시 템플릿으로 폴백**입니다.
API는 필터만 구현하고 폴백을 빼면 안 됩니다. 폴백이 규제 방어의 강한 쪽입니다.

## 3. API 모듈을 위한 권고 (최종 리뷰어)

1. **DB → 엔진 입력 변환을 엔진 안에 두세요.** DB는 주차별 스냅샷이고 `CaseInput`은 항목별 시계열입니다.
   `CaseInput.fromSnapshots(...)` 같은 팩토리를 엔진에 두면 정렬·축 불변식이 한 곳에서 강제됩니다.
   컨트롤러에서 마감에 쫓기며 다시 구현하면 놓칩니다.
2. **`ORDER BY week`는 선택이 아닙니다.** 다만 엔진이 이제 자체 정렬하므로 조용히 틀리지는 않습니다.
3. **`PipelineResult`를 병렬 리스트 대신 `List<Question>`으로 바꾸세요.**
   `selected[i]`와 `sentences[i]`의 대응이 지금은 주석에만 있습니다.
   API는 질문마다 LLM 문장과 템플릿 문장을 함께 들고 다녀야 하는데, 병렬 리스트로는 깨지기 쉽습니다.
   같이: `PipelineResult`의 다섯 리스트를 방어 복사하세요.
4. **`Detection`에 주차를 넘어 안정적인 식별자가 없습니다.** `equals`에 `duration`이 들어가는데 매주 바뀝니다.
   `(type, items, signal, timeTag)`로 만든 `key()`가 있어야 "이 질문은 지난주에 이미 드렸다"를 할 수 있습니다.
5. **LLM은 템플릿 뒤에 두세요.** `sentences`가 폴백이자 프롬프트의 기준 문장입니다.
6. **데모 버튼은 `DemoSeed.stroke()`에 직접 연결하세요.** DB를 거치지 않으면 마이그레이션이 데모를 못 깹니다.
7. **엔진 예외 메시지에 항목·주차를 넣으세요.** 일부는 이미 들어갔지만 `Labels.of`는 아직입니다.

## 4. 스펙(README)에 반영할 것

최종 리뷰어가 스펙 자체의 문제로 분류한 것들입니다. 세 개는 이미 반영했고, 하나가 남았습니다.

- ✅ §5 자유 기록의 주차 규약 (단, 1번의 오류 수정 필요)
- ✅ §5 관찰 세트가 MVP에서는 컴파일 상수라는 명시
- ✅ §6 주차 계산이 기록된 주 기준이라는 명시와 근거
- ✅ §7 우선순위 목록이 9칸으로 10종류를 덮는 이유
- ⬜ **§10 시드가 (e) 규칙에 대해 불충분하게 기술돼 있습니다.** 자유 기록을 3·4·6주만 적어놨는데,
  §7 (e)의 기대 문장 "4주 중 3주"가 나오려면 창 안에 기록된 주가 4개여야 합니다.
  구현은 1·2·5주에 태그 없는 항목을 넣어 해결했습니다. 이 규약을 §10에도 적어두세요.

## 5. 남겨둔 사소한 지적 (API 모듈과 함께)

최종 리뷰어가 "API 모듈과 함께 고칠 것"으로 분류한 것들입니다.

- 신호 짝짓기 규칙의 부정 테스트가 비대칭입니다. 두 규칙 중 하나만 격리 테스트가 있습니다.
- 축 규칙 하나에 반대 방향 부정 테스트가 없습니다. 형제 규칙에는 있습니다.
- 질문 선택 비교자의 첫 항목 동점 처리가 실제 동점으로 검증된 적이 없습니다.
- `PipelineResult`의 방어 복사 (3번 권고와 함께).

**남겨두기로 한 것들** (리뷰어 판단): `Observation`의 null 검사 테스트, 리스트 이중 복사,
`SignalWeek`의 null NPE, 카탈로그의 중복 선형 탐색, 규칙 (a)/(b)의 가드 중복(의도적 보호),
`CrossDetector`의 143줄, `DemoSeed.put`의 중복 덮어쓰기.

**범위 밖 관찰 두 가지:**

- `WeeklyNote`에 `week >= 1` 검증이 없습니다. `Observation`에는 있습니다. 0이나 음수 주차가 창을 차지합니다.
- `CaseInput`은 `series`만 검증하고 `signals`/`notes`는 안 합니다. 중복 주차 계약이 감지기 깊은 곳에서만 강제됩니다.
- `CaseInput`의 `Map.copyOf`는 얕은 복사라, 호출자가 안쪽 맵 참조를 들고 있으면 생성 후 축을 추가해 검증을 우회할 수 있습니다.
