# 백엔드 — 구현된 것

2026-09-06 기준. **구현 완료 두 계획 중 두 번째까지 끝났고, 세 번째(LLM 연동)가 남았습니다.**

이 문서는 코드를 검토하려는 사람을 위한 것입니다. 제품이 무엇이고 왜 이렇게 설계했는지는 최상위 `README.md`(제품 스펙)에 있고, 이 문서는 **그 스펙이 코드의 어디에 어떻게 들어갔는지**만 다룹니다.

| `../docs/superpowers/specs/2026-09-05-api-design.md` | API 계약. 데이터·주차 규칙·엔드포인트 |

## 0. 지금 어디까지 왔는가

| 단계 | 상태 |
| --- | --- |
| `engine` — 판정 규칙 엔진 | ✅ 완료 |
| `api` (api-core) — 저장·조회·화면 데이터 | ✅ 완료 |
| **api-llm — LLM 문장 다듬기와 가드레일** | ❌ **미착수** |
| frontend — React PWA | ❌ 미착수 |
| infra — EC2·Compose·Caddy·노트북 Ollama | ❌ 미착수 |

**지금 상태로도 제품은 동작합니다.** 질문 문장이 템플릿으로 나오고, LLM은 그 문장을 더 자연스럽게 다듬는 역할만 남았습니다. §8 가드레일 3번의 폴백이 곧 지금 상태입니다.

```
engine  30개 파일 1,112줄   테스트 14개 파일 1,830줄 → 112개 통과
api     74개 파일 2,600줄   테스트 16개 파일 1,531줄 →  59개 통과
```

테스트가 본문보다 많습니다. 의도한 것입니다. 이 제품은 출력이 전부 한국어 문장이라, 문장을 글자 단위로 고정하지 않으면 회귀를 눈으로 잡을 수 없습니다.

## 1. 두 모듈로 나눈 이유

```
backend/
  engine/   순수 자바. 런타임 의존성 0. 판정이 여기 전부 있다
  api/      Spring Boot 3.5. 저장하고, 엔진을 부르고, 화면용으로 모양을 바꾼다
```

**엔진에 Spring이 없습니다.** 이게 "판정은 코드가 하고 언어만 AI가 한다"는 발표 문장의 근거입니다. 엔진은 입력을 받아 판정을 내는 순수 함수 덩어리라, 같은 입력에 항상 같은 출력이 나오는 걸 테스트로 증명할 수 있습니다. `PipelineSeedTest`가 파이프라인을 두 번 돌려 결과가 같은지 봅니다.

**API에는 판정이 없습니다.** 저장하고, 엔진을 부르고, 층별로 무엇을 보여줄지 고릅니다. 검토하실 때 API 쪽에서 `if (status == ...)` 같은 걸 보시면 그건 층별 필터링이지 판정이 아닙니다.

## 2. 엔진 — 판정이 사는 곳

읽는 순서를 이렇게 잡으시면 편합니다.

### 2.1 값 하나가 어떻게 판정되는가

```
Observation(week, value, source)   한 주 한 축의 관찰값
        ↓  여러 주 모으면
SilenceGate.judge(List<Observation>) → Verdict
```

`SilenceGate`(75줄)가 제품의 심장입니다. 주차별 값 배열을 받아 넷 중 하나로 분류합니다.

| 판정 | 뜻 |
| --- | --- |
| `NO_CHANGE` | 변화 없음 |
| `OBSERVED_ONCE` | 1주만 달라짐. 아직 변화라고 부르지 않음 |
| `SUSTAINED` | 2주 이상 유지 |
| `FLUCTUATING` | 갔다 돌아옴 |

**`OBSERVED_ONCE`가 이 엔진의 존재 이유입니다.** 한 번의 관찰과 유지된 관찰을 구분하지 않으면 노이즈를 이야기로 파는 제품이 됩니다.

규칙 순서가 중요합니다. 흔들린 뒤에도 4주 유지되면 다시 `SUSTAINED`로 돌아옵니다(회복). 이 순서가 뒤집히면 `SilenceGateTest`의 아홉 번째 줄만 실패합니다. 스펙 §6의 예시 표 10줄이 그대로 파라미터 테스트로 들어가 있습니다.

`Verdict`는 판정과 함께 **`trajectory`(전체 궤적)를 항상 반환합니다.** 판정이 무엇이든 원본 값을 버리지 않습니다. 층 3이 이걸 씁니다.

### 2.2 항목 사이의 어긋남 찾기

```
CrossDetector.detect(set, verdicts, patterns, notes) → List<Detection>
```

항목별 판정을 모아 여덟 가지 어긋남을 찾습니다. 스펙 §7의 (a)~(h)가 그대로 메서드입니다.

| 규칙 | 잡는 것 |
| --- | --- |
| (a) 상승 대 정체 | **검증된 질문 1을 만드는 규칙** |
| (b) 상승 대 하락 | 항목별로 엇갈리는 경우 |
| (c) 참여 × 통증 신호 | 세 갈래. **정체+통증이 검증된 질문 2** |
| (d) 흔들림 | 방향 전환 2회 이상 |
| (e) 시간대 | 자유 기록 태그가 4주 중 3주 |
| (f) 도구 변화 | 도움은 그대로인데 워커→지팡이 |
| (g) 마비 쪽 손 | **도움은 덜 필요해졌는데 마비된 손을 덜 씀** |
| (h) 일관성 하락 | 도움은 그대로인데 좋은 날만 |

(a)는 그룹을 넘어 비교합니다. 초기 설계에서 같은 그룹으로 제한했다가 풀었습니다. 화장실은 자기관리, 걷기는 이동이라 제한이 있으면 치료사가 가장 좋다고 한 질문이 안 나옵니다. 코드 어디에도 `group`을 참조하는 곳이 없습니다.

### 2.3 셋 고르기와 문장 만들기

```
QuestionSelector.select(detections, set) → 최대 3개
Templates.render(detection, set, verdicts) → 한국어 문장
```

**LLM이 고르지 않습니다.** 종류별로 하나씩 돌아가며 뽑습니다. 단순 정렬이면 시끄러운 한 종류가 세 자리를 다 먹습니다. `QuestionSelectorTest`에 두 방식이 다른 답을 내는 케이스가 있어서, 나중에 단순 정렬로 바꾸면 테스트가 잡습니다.

`Templates`는 문장 조립과 **금지 어휘 검사**를 합니다.

```java
containsForbiddenWord(String)   19개 금지어. NFC 정규화 후 부분 문자열 검사
isQuestion(String)              물음표로 끝나는가
isSafe(String)                  둘 다
```

금지어에 활용형이 따로 들어가 있습니다. "좋아지"만으로는 "좋아졌습니다"도 "좋아짐"도 안 걸립니다. 한국어 과거형이 지+었→졌으로 줄어들기 때문입니다.

**`ReadmeConformanceTest`(11개)를 먼저 보시길 권합니다.** 스펙의 각 절이 "이렇게 동작해야 한다"고 쓴 것을 검사 항목으로 옮긴 것입니다. 항목 이름에 절 번호가 붙어 있어서, 실패하면 스펙과 코드 중 어디가 틀렸는지 바로 보입니다. 여기 템플릿 전수 조사도 있습니다. 가능한 값 조합으로 문장 3천 개 이상을 실제로 만들어 금지 어휘와 질문형을 검사합니다.

### 2.4 API가 부르는 것은 두 개뿐

```java
CaseInput.fromWeeks(ObservationSet.STROKE, List<WeekRecord>)   주차별 기록 → 엔진 입력
Pipeline.run(caseInput) → PipelineResult                        판정·감지·선택·문장
```

`PipelineResult`가 판정(`verdicts`), 신호 패턴(`patterns`), 감지 전부(`detections`), 선택된 셋(`selected`), 문장(`sentences`)을 함께 돌려줍니다. 층마다 이 중 다른 것을 씁니다.

## 3. API — 저장하고 층별로 보여주기

### 3.1 데이터

테이블 다섯 개. 스키마는 Flyway가 소유하고 Hibernate는 손대지 않습니다(`ddl-auto: none`).

| 테이블 | 담는 것 |
| --- | --- |
| `cases` | 시작일, 진단, 마비 쪽, 말로 표현 가능 여부, 외래 예약일, 복구 코드 해시 |
| `guardians` | 케이스당 여러 명. 관계(딸·아들)와 토큰 해시 |
| `therapist_links` | 읽기 전용 링크. 해시만. 폐기 가능 |
| `snapshots` | **주차별 전체 스냅샷.** 본문은 JSONB 한 컬럼 |
| `question_cache` | 케이스당 최신 질문 하나 |

**주차 스냅샷이 층 1입니다.** 값마다 출처가 붙습니다.

```json
{ "level": {"value": 3, "source": "CONFIRMED"}, "aid": null, ... }
```

`CONFIRMED`는 보호자가 직접 고른 값, `CARRIED`는 "달라진 것 없음"을 눌러 지난주에서 복사된 값입니다. 이걸 구분하지 않으면 치료사용 표에서 실제 관찰 1회와 "없음" 탭 5회가 같은 숫자로 보입니다.

스냅샷마다 작성자도 붙습니다. 대리 응답의 편향은 사람마다 다르므로, 작성자가 바뀌면 치료사용 요약에 그 지점을 표시합니다.

### 3.2 주차 규칙

`WeekCalculator`가 서울 기준으로 계산합니다.

```
week = floor((오늘 - 시작일).days / 7) + 1
```

- 온보딩이 **1주차 기준선**입니다. 주간 기록은 2주차부터.
- 경로의 주차가 오늘 주차와 달라야 하면 409. 과거 소급 기록은 범위 밖입니다.
- 같은 주에 다시 저장하면 덮어씁니다. 행이 없는 주가 곧 결측입니다.
- **4의 배수 주는 전체 재확인.** 8항목을 전부 다시 묻습니다. 매주 "변화 없음"만 누르면 서서히 나빠지는 궤적을 놓치기 때문입니다.

### 3.3 검증이 일어나는 곳

`SnapshotAssembler`가 유일한 관문입니다. 요청 DTO에는 Bean Validation이 없습니다.

- 변경한 항목은 **적용되는 모든 축**을 보내야 하고 전부 `CONFIRMED`가 됩니다.
- 적용 안 되는 축(화장실에 보조 도구)에 값을 보내면 거부합니다.
- 마비 쪽을 모르는 케이스에 마비 쪽 손 값을 보내면 거부합니다.
- 나머지 항목은 직전 기록에서 `CARRIED`로 복사합니다. **직전 주가 결측이면 그보다 앞의 최신 기록**을 씁니다.
- 비언어 관찰이 켜진 케이스는 매주 신호를 물어야 합니다. `{}`가 "물어봤고 없었다"입니다.

`SnapshotAssemblerTest`(10개)가 스프링 없이 이 규칙들을 직접 검사합니다. 메시지 문자열까지 확인하므로 어느 규칙이 걸렸는지 테스트가 압니다.

### 3.4 엔드포인트

| 메서드 | 경로 | 인증 | 화면 |
| --- | --- | --- | --- |
| GET | `/catalog` | 없음 | 전부. 한국어 라벨 전체 |
| POST | `/cases` | 없음 | 1 온보딩 |
| POST | `/guardians/recover` | 없음 | 새 기기·두 번째 보호자 |
| GET | `/me` | 토큰 | 2 이번 주차·분기 정보 |
| PATCH | `/me` | 토큰 | 외래 예약일 수정 |
| PUT | `/me/weeks/{week}` | 토큰 | 2 주간 기록 |
| GET | `/me/progress` | 토큰 | 3 경과 (침묵 게이트) |
| GET | `/me/trajectory` | 토큰 | 3-b 전체 궤적 |
| GET | `/me/prep-card` | 토큰 | 4 진료 준비 카드 |
| PUT | `/me/prep-card/extra` | 토큰 | 4 보호자 추가 질문 |
| POST | `/me/therapist-link` | 토큰 | 5 링크 발급 |
| GET | `/t/{token}` | 링크 토큰 | 5 치료사용 요약 |
| POST | `/demo` | 없음 | 데모 |
| GET | `/health` | 없음 | 운영 |

**`/catalog`을 먼저 보세요.** 항목 8개의 코드와 두 가지 표시 문구, 축 4개의 값별 라벨, 신호 동작·종류, 시간대, 수면 단계가 전부 들어 있습니다. 프론트가 한국어를 하드코딩할 필요가 없습니다.

### 3.5 인증

Spring Security를 쓰지 않습니다. 토큰을 케이스에 매핑하는 것뿐이라 과합니다.

- 서블릿 필터가 `/me`와 `/me/**`만 가로챕니다. `X-Guardian-Token` 헤더를 SHA-256으로 해시해 조회합니다.
- 평문 토큰은 저장하지도 로그에 남기지도 않습니다.
- CORS 필터가 그보다 먼저 돌고, 프리플라이트 `OPTIONS`는 인증을 건너뜁니다. 안 그러면 프론트의 모든 인증 요청이 프리플라이트에서 401로 막힙니다.
- 복구 코드는 케이스당 하나, 8자리(헷갈리는 `I O 0 1` 제외). 온보딩 응답에서 **한 번만** 보여주고 해시만 남깁니다.

## 4. 3층 분리가 코드의 어디에 있는가

**여기가 이 제품의 핵심이고, 검토하실 때 가장 볼 만한 부분입니다.**

### 층 1 — 기록: `snapshots` 테이블

무엇도 버리지 않습니다. 되돌아간 변화, 1주만 관찰된 것, 자유 기록 원문 전부. 델타가 아니라 주차별 전체 스냅샷입니다.

완화가 둘 있습니다. 같은 주 덮어쓰기는 이전 본문을 남기지 않고, 비언어 관찰이 꺼진 케이스에 보낸 신호는 버립니다.

### 층 2 — 보호자 화면: `ProgressService`

침묵 게이트가 **여기서만** 작동합니다.

```java
if (status == OBSERVED_ONCE || status == SUSTAINED) → changes 에 넣는다
else if (status == FLUCTUATING) → 전환인지만 본다
// NO_CHANGE 는 아무 분기에도 안 걸린다
```

흔들림은 기본 화면에서 숨깁니다. 매주 오르내림을 그대로 보여주면 "좋아졌어요 → 나빠졌어요"가 반복되고 보호자가 이탈합니다.

**단, 유지에서 흔들림으로 넘어간 그 주에만** 문구를 한 번 보여줍니다. 지난주에 "3주째 유지"를 봤는데 이번 주에 그 문장이 말없이 사라지면 그것도 작은 롤러코스터이기 때문입니다. 이걸 어떻게 아느냐면, 엔진이 결정론적이라서 **마지막 주를 뺀 입력으로 한 번 더 돌려** 비교합니다. 다음 주에는 지난주까지도 이미 흔들림이라 자연히 사라집니다. 특별 처리가 없습니다.

층 2 문장은 API가 조립합니다. 이어붙이는 조각이 전부 컴파일된 상수 표(`Item.phrase`, `AxisLabels.of`, `Labels.of`)와 정수뿐이라, 보호자 텍스트나 DB 텍스트가 이 문장에 도달할 경로가 없습니다. **나올 수 있는 문장이 유한합니다.**

### 층 3 — 치료사용: `TherapistSummaryService` + `TrajectoryMapper`

층 2가 숨긴 흔들림을 그대로 보여주고, **판정은 하나도 넣지 않습니다.**

이게 관례가 아니라 구조입니다. `TrajectoryMapper`는 스냅샷 본문을 직접 읽고 `Verdict`나 `Status`를 **import조차 하지 않습니다.** 판정을 흘릴 수가 없습니다. 엔진을 돌린 뒤 필드를 걸러내는 방식이었다면 관례였을 겁니다.

`TherapistControllerTest`가 응답 JSON 원문에 `SUSTAINED`, `FLUCTUATING`, `"status"`, `"duration"`, `상승`, `하락`이 없는지 검사합니다.

한 가지 알아두실 것. 생성된 질문 문장은 치료사 페이지에 나갑니다. 그 문장들은 기간("6주째 그대로입니다")과 방향을 담고 있습니다. 이건 의도한 것이고 스펙 §9 화면 5에 근거를 적었습니다. 이 화면의 목적이 부재한 보호자의 대리 진술이고, 보호자가 묻고 싶었던 것도 그 진술의 일부이기 때문입니다.

## 5. 규제 경계가 지켜지는 방식

스펙 §2가 금지한 것은 필터로 막는 게 아니라 **구조로 도달 불가능하게** 만들어져 있습니다.

| 층 | 문장이 나오는 곳 | 왜 안전한가 |
| --- | --- | --- |
| 층 2 | `ProgressService.message` | 상수 표만 이어붙임. 가능한 문장이 유한 |
| 층 4·5 | 엔진 `Templates.render` | 10가지 템플릿. 전수 조사 3천 건 검증 |
| 층 3 자유 기록 | 보호자 원문 | 보호자의 말이지 제품의 주장이 아님 |

감소는 "악화"가 아니라 "도움이 더 필요해지셨습니다"로 씁니다. 가치 판정을 피하는 것이 규제 방어이자 보호자에게 잘못된 확신을 주지 않는 방법입니다.

**LLM이 붙는 순간 이 그림이 바뀝니다.** 지금은 생성되는 문장이 전부 상수 표에서 나와 금지 어휘 목록이 좁아도 안전하지만, LLM이 문장을 쓰면 그 목록이 유일한 방어선이 됩니다. 현재 목록은 §2가 금지한 다섯 갈래 중 한 갈래만 막습니다. **엔진 후속 문서 2번을 LLM 계획 전에 처리해야 합니다.**

## 6. 돌려보기

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)   # 이 맥 기본 java가 26이라 Gradle이 안 뜹니다
cd backend

./gradlew test                    # 엔진 112 + API 59, 도커 불필요 (H2)

docker compose up -d              # Postgres 16
./gradlew :api:bootRun            # http://localhost:8080
```

데모를 한 번 돌려보시면 전체가 한눈에 들어옵니다.

```bash
curl -s -X POST localhost:8080/demo | tee /tmp/d.json | jq
T=$(jq -r .guardianToken /tmp/d.json)

curl -s localhost:8080/me/prep-card -H "X-Guardian-Token: $T" | jq '.questions[].sentence'
curl -s "localhost:8080$(jq -r .therapistUrl /tmp/d.json)" | jq
```

준비 카드에서 이 세 문장이 나와야 합니다.

```
화장실 이용은 혼자 하심으로 바뀌셨는데 집 안에서 걷기는 6주째 그대로입니다. 집 안에서 걷기는 왜 안 늘고 있을까요?
일어설 때 얼굴을 찡그리시는 걸 4주 중 3주 봤습니다. 통증일 수 있을까요?
식사는 혼자 하심으로 바뀌셨는데 마비된 손은 안 씀으로 바뀌었습니다. 괜찮은 걸까요?
```

두 번째가 물리치료사가 "이런 질문들은 너무 좋다"고 한 문장이고, 템플릿만으로 글자 하나 안 틀리고 나옵니다. 세 번째는 마비 쪽 손 축에서 나온 질문으로, 치료사가 병원에서는 볼 수 없다고 한 장면입니다.
